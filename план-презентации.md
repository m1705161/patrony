## 1. Титул
- **Текст:** тема + подзаголовок «как теория переходит в инженерные расчёты».
- **Картинка:** тонкая визуализация (фрагмент диаграммы кластера) справа/фоном.
- **Подпись:** стек курса (Postgres, Citus, Patroni, Greenplum, Spark, S3, Trino, K8s).

## 2. Зачем это всё (мотивация)
- **Текст (2 колонки):** вертикальное vs горизонтальное масштабирование.
- **Диаграмма:** одна машина → упрётся в потолок → много узлов.
- **Подпись:** «одна большая машина» дорожает нелинейно — масштабируемся вширь.

## 3. CAP и PACELC
- **Диаграмма (центр):** треугольник CAP (C-A-P по вершинам).
- **Текст (края):** PACELC — выбор в partition (A/C) и в штатном режиме (L/C).
- **Подпись:** из трёх гарантий всегда выбираем две — в этом корень компромиссов.

## 4. Эволюция систем
- **Диаграмма/таймлайн:** MPP → NoSQL → NewSQL.
- **Текст:** Teradata/Greenplum, Dynamo/Cassandra/BigTable, Spanner/CockroachDB.
- **Подпись:** паттерны одни — меняется только реализация.

## 5. Теория: что такое шардирование
- **Текст:** шардинг = горизонтальное партиционирование по узлам; партиционирование (логическое) vs шардирование (физическое).
- **Диаграмма:** данные расщепляются на N узлов по ключу.
- **Подпись:** один логический датасет — много физических шардов.

## 6. Стратегии выбора шарда
- **Диаграмма (4 мини-блока):** hash / range / directory(list) / consistent hashing — с плюсами-минусами.
- **Текст:** hot spot, skew, rebalancing (почему дорого).
- **Подпись:** ключ шардирования решает, равномерно ли лягут данные и запросы.

## 7. Теория: что такое репликация
- **Диаграмма:** leader–follower / multi-leader / leaderless — одна схема на модель.
- **Текст:** синхронная vs асинхронная, trade-off; quorum R + W > N.
- **Подпись:** репликация — плата доступностью за отказоустойчивость и скорость чтения.

## 8. Согласованность и консенсус
- **Диаграмма:** спектр strong → eventual (+ causal, read-your-writes, monotonic reads).
- **Текст:** Raft/Paxos и паттерн leader election (кто такой primary — решает quorum).
- **Подпись:** где нужен консенсус — там leader election (Patroni/etcd).

## 9. Ядро: партиционирование в Postgres  (начало расчётов)
- **Текст:** RANGE / LIST / HASH, partition key, partition pruning.
- **Диаграмма:** таблица распилена на партиции; планировщик трогает только нужные.
- **Формула:** число партиций = объём / размер партиции (окно retention).
- **Подпись:** pruning = бесплатный выигрыш, если ключ выбран верно.

## 10. Ядро: шардирование через Citus
- **Диаграмма:** coordinator + N workers; distribution column → hash-шардинг.
- **Текст:** `shard_count` (32) × `shard_replication_factor`.
- **Формула:** воркеры = f(объём, QPS); строки = total / shard_count.
- **Подпись:** распределение строк видно по `shard_count` — его и считаем.

## 11. Ядро: репликация в Postgres
- **Диаграмма:** primary → replicas, поток WAL; блок logical replication (pub/sub).
- **Текст:** streaming vs логическая; lag через `pg_stat_replication`.
- **Формула:** lag в сек/байтах; `synchronous_commit` (on / remote_apply).
- **Подпись:** trade-off «задержка vs гарантия доставки» — одним параметром.

## 12. Ядро: HA — Patroni + etcd
- **Диаграмма:** etcd (RAFT) ↔ Patroni ↔ primary/replica; стрелка failover.
- **Текст:** RTO = время failover, RPO = потерянные (недореплицированные) коммиты.
- **Подпись:** RPO/RTO — два числа, по которым оценивают HA, а не «у нас реплика есть».

## 13. Ядро: сеть и хранилище
- **Формула (крупно):** `write_rate × replication_factor` (+ basebackup с нуля).
- **Текст:** storage amplification = replication_factor; полные копии standby.
- **Подпись:** репликация — это прежде всего трафик и диск, их считаем честно.

## 14. Ядро: сквозной пример «от данных к железу»
- **Диаграмма:** конвейер N ТБ + QPS → воркеры → партиции → реплики → сеть.
- **Текст/формулы:** пошагово: воркеры Citus, партиции, standby, lag, что закрывает Patroni.
- **Подпись:** вся теория сходится в один расчёт — из него видно, где узкое место.

## 15. Те же паттерны в стеке курса (обзор)
- **Диаграмма/таблица:** Postgres | Greenplum | Spark | S3 | Trino | K8s — «как это названо там».
- **Текст:** distribution key = hash-шардинг; segment mirror = реплика; ReplicaSet = реплика и т.д.
- **Подпись:** узнаёшь паттерн в любом туле — теория одна.

## 16. Практика: Postgres + Citus
- **Диаграмма:** docker-compose coordinator + workers; стрелка «распределить таблицу».
- **Текст:** план запроса, распределение строк по шардам — что смотрим.
- **Подпись:** глазами видно шардирование — сколько строк уехало на каждый worker.

## 17. Практика: Patroni + etcd (failover)
- **Диаграмма:** последовательность сбоя primary → leader election → промоут нового primary.
- **Текст:** как «сломать» primary и замерить время failover.
- **Подпись:** RTO из слайда 12 превращаем в секундомер.
